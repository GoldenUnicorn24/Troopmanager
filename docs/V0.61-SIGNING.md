# Troopmanager v0.61+ signing policy

Starting with v0.61.0, installable release-test APKs use one persistent private signing key.

- Application ID: `com.goldenunicorn.troopmanager`
- Signing family start: `v0.61.0`
- Alias: `troopmanager-update`
- Certificate SHA-256: `FE:4A:83:46:D9:63:6B:C5:D9:6A:99:E0:7A:44:DD:B4:E1:EF:BF:CA:95:C4:45:2B:78:A5:5E:E6:2C:51:E5:3C`
- Private keystore: deliberately NOT committed to this public repository.
- Private backup location used by the project owner: ChatGPT Library `/Troopmanager/Signing/Troopmanager-v061-Signing-Backup-KEEP-PRIVATE.zip`.

Every future installable update in this family must be signed with that same private key and use a higher Android `versionCode`.

The GitHub Actions debug APK is an unsigned input for the persistent release-test signing step from the perspective of update identity: do not distribute a fresh CI debug-signed build as an update family. The CI workflow exports the matching Android Build Tools `apksigner` helper so the built APK can be re-signed with the persistent private key outside the public repository.

The previous locally delivered v0.4/v0.45 signing key is not available, therefore Android cannot accept v0.61 as an in-place update over that older signing family. v0.61 establishes the durable family for v0.61 and later.
